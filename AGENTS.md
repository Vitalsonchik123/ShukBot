# AGENTS.md

## О проекте

ShukBot — RAG-приложение для поиска ответов по документам. Стек: Python (бэкенд), BM25 (поиск), LLM API (генерация ответов), HTML/CSS/JS (фронтенд).

## Структура

- `spec/` — только документация, код здесь не пишется
  - `spec/product/` — продукт, пользователи, сценарии
  - `spec/tech/` — архитектура, API, RAG и поиск
- `src/` — весь исходный код приложения
- `data/` — документы базы знаний (не коммитить большие файлы без необходимости)
- `design/` — макеты и прототипы интерфейса
- `STATUS.md` — текущее состояние проекта и следующий шаг
- `CHANGE_HISTORY.md` — история изменений

## Порядок работы

Перед любым изменением кода:

1. Прочитай `STATUS.md`, `spec/product/` и `spec/tech/`.
2. Если меняется поведение приложения — сначала обнови нужную спецификацию.
3. Внеси изменение в код.
4. Запусти проверки (тесты, а для поиска — benchmark) и приведи их результат.
5. Добавь запись в `CHANGE_HISTORY.md` и обнови `STATUS.md`.

## Ключевые ограничения

- Поиск BM25 реализуется самостоятельно в `src/`. Не используйте готовые поисковые индексы и библиотеки ранжирования (`rank_bm25`, SQLite FTS5, Elasticsearch, Whoosh и т. п.). Для лемматизации готовые библиотеки допустимы (см. `spec/tech/rag.md`).
- Нейросеть отвечает только на основе найденных фрагментов. Если фрагментов нет — система сообщает, что информации нет, а не генерирует ответ.
- Ключи API хранятся в `.env` и не коммитятся.

## Правила работы

- Не изменяйте файлы в `spec/` без явного запроса — это проектная документация.
- Не добавляйте зависимости без обновления `requirements.txt` (будет создан позже).
- Все новые файлы с кодом кладите в `src/`.
- Коммиты пишите на английском в формате: `тип: краткое описание` (например, `docs: add RAG description`).
- Перед коммитом проверяйте, что структура папок не нарушена.
