# RAG и поиск BM25 в ShukBot

## Что такое RAG

RAG (Retrieval-Augmented Generation) — подход, при котором нейросеть генерирует ответ не «из головы», а на основе найденных фрагментов документов. Это снижает риск галлюцинаций и позволяет ссылаться на источники.

## Этапы RAG-пайплайна

### 1. Индексация документов

При загрузке документ разбивается на фрагменты (чанки) — обычно по абзацам или 300–500 символов. Каждый фрагмент сохраняется в поисковый индекс.

### 2. Поиск (Retrieval)

Когда пользователь задаёт вопрос, система ищет в индексе наиболее релевантные фрагменты. Используется алгоритм **BM25**.

### 3. Генерация (Generation)

Найденные фрагменты вместе с вопросом отправляются в нейросеть. Промпт содержит явную инструкцию: «Используй только этот контекст».

## Как работает BM25

BM25 (Best Matching 25) — алгоритм ранжирования, который оценивает релевантность документа запросу на основе:

- **Частоты термина** (TF) — чем чаще слово встречается в фрагменте, тем выше релевантность.
- **Обратной частоты документа** (IDF) — чем реже слово встречается во всей базе, тем оно важнее.
- **Нормализации длины** — длинные фрагменты не должны получать преимущество только за счёт размера.

Формула (упрощённо):
score(D, Q) = Σ IDF(qi) · (tf(qi, D) · (k1 + 1)) / (tf(qi, D) + k1 · (1 - b + b · |D| / avgdl))


где `k1` и `b` — параметры (обычно `k1 = 1.2–2.0`, `b = 0.75`).
