# RAG и поиск BM25 в ShukBot

## Что такое RAG

RAG (Retrieval-Augmented Generation) — подход, при котором нейросеть генерирует ответ не «из головы», а на основе найденных фрагментов документов. Это снижает риск галлюцинаций и позволяет ссылаться на источники.

## Этапы RAG-пайплайна

1. **Индексация** — документы разбиваются на фрагменты, фрагменты проходят предобработку и попадают в индекс.
2. **Поиск (Retrieval)** — вопрос проходит ту же предобработку, индекс возвращает Top-K фрагментов по BM25.
3. **Генерация (Generation)** — найденные фрагменты вместе с вопросом отправляются в нейросеть с инструкцией «используй только этот контекст».

## Корпус и документ

- **Корпус** — все файлы из `data/`: лекции, методички и курсовые по АСОИУ.
- **Документ** (единица индексации) — фрагмент текста: абзац исходного файла. Абзацы длиннее ~1000 символов делятся по границам предложений, слишком короткие (заголовки, номера страниц) склеиваются со следующим абзацем.
- У каждого фрагмента хранятся: идентификатор, имя файла, номер страницы и исходный текст — они нужны для вывода источников.

Абзац выбран потому, что он обычно содержит одну законченную мысль: такой фрагмент достаточно короткий для точного поиска и достаточно полный для ответа.

## Предобработка текста

Одинаковая для фрагментов и для запросов.

1. **Нижний регистр.** «АСОИУ» и «асоиу» должны совпадать; различать регистр в нашей задаче незачем.
2. **Токенизация.** Токен — отдельное слово: последовательность букв и цифр (регулярное выражение `\w+`). Знаки препинания отбрасываются. Подход простой и достаточный для текстов лекций.
3. **Лемматизация** — библиотека `pymorphy3`. Русский язык сильно флективен: «системы», «системой», «систему» без лемматизации — разные термы, и запрос не найдёт фрагмент, где слово стоит в другом падеже. Готовая библиотека допустима: самостоятельно реализуется только поисковый индекс.
4. **Стоп-слова** — удаляются предлоги, союзы, частицы и вопросительные слова («и», «в», «на», «что», «это», «такой» и т. п.). Они встречаются почти во всех фрагментах и только добавляют шум.

Пример: «Что такое АСОИУ?» → `["асоиу"]`; «Какие функции выполняет система?» → `["функция", "выполнять", "система"]`.

## Индекс

Индекс реализуется самостоятельно, без готовых поисковых библиотек. Хранит:

- обратный индекс: терм → {идентификатор фрагмента: TF};
- длину каждого фрагмента в термах `|d|`;
- число фрагментов `N` и среднюю длину `avgdl`.

Индекс строится один раз командой индексации и сохраняется в файл в `data/`.

## Как работает BM25

- **TF(t, d)** — число вхождений терма `t` во фрагмент `d`.
- **DF(t)** — число фрагментов, в которых встречается терм `t`.
- **IDF** — чем реже терм встречается в корпусе, тем он важнее:

```
IDF(t) = ln(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
```

- **Оценка фрагмента** `d` по запросу `q`:

```
BM25(q, d) = Σ_{t ∈ q} IDF(t) · TF(t, d) · (k1 + 1) / (TF(t, d) + k1 · (1 - b + b · |d| / avgdl))
```

Параметры:

- `k1` — насколько быстро «насыщается» вклад частоты терма; начальное значение `1.5` (обычный диапазон 1.2–2.0);
- `b` — степень нормализации по длине фрагмента; начальное значение `0.75`. При `b = 0` длина не учитывается, при `b = 1` — полная нормализация.

Значения уточняются по результатам проверки качества.

## Выдача результатов

- Фрагменты сортируются по убыванию BM25, берутся первые `k` (начальное значение `k = 5`).
- Фрагменты с нулевой оценкой не возвращаются. Если не осталось ни одного — нейросеть не вызывается, пользователь получает сообщение «в загруженных документах нет информации по этому вопросу».

## Промпт для нейросети

- Системная инструкция: отвечать на русском, только на основе приведённых фрагментов; если в них нет ответа — так и сказать.
- Фрагменты с указанием источника (файл, страница).
- Вопрос пользователя.

## Проверка качества поиска

Проверяется только этап поиска.

- **Тестовый набор:** запросы, равномерно покрывающие темы корпуса. Для каждого запроса вручную отмечаются релевантные фрагменты — не менее трёх. Запросы формулируются своими словами, а не копируются из текста документов.
- **Recall@k** — доля релевантных фрагментов, попавших в первые `k` результатов, усреднённая по запросам:

```
Recall@k = (1 / |Q|) · Σ_i |R_i ∩ Top_k(q_i)| / |R_i|
```

- **MRR** — насколько высоко стоит первый релевантный фрагмент:

```
MRR = (1 / |Q|) · Σ_i 1 / rank_i
```

где `R_i` — множество релевантных фрагментов для запроса `q_i`, `rank_i` — позиция первого релевантного фрагмента в выдаче.

По результатам делается вывод о качестве ранжирования и подбираются `k1`, `b`, `k` и список стоп-слов.
