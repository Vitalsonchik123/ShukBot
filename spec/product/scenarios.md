# Сценарии использования ShukBot

## Сценарий 1: Поиск определения термина

**Актёры:** Студент, Система.

**Предусловие:** В базе загружены лекции по АСОИУ.

**Основной поток:**

1. Студент открывает веб-приложение ShukBot в браузере.
2. Видит поле ввода с подсказкой «Введите ваш вопрос…» и кнопку «Найти».
3. Вводит вопрос: *«Что такое АСОИУ?»*
4. Нажимает кнопку «Найти».
5. Система показывает индикатор загрузки.
6. Система обрабатывает вопрос: приводит слова к начальной форме и убирает служебные слова («что», «такой»). Остаётся ключевое слово «асоиу».
7. По алгоритму BM25 находит наиболее релевантные фрагменты (Top-K) с этим словом.
8. Отправляет вопрос и фрагменты в нейросеть.
9. Нейросеть формирует ответ: *«АСОИУ — это автоматизированная система обработки информации и управления…»*
10. Система выводит ответ в области результата.
11. Под ответом отображаются источники: названия документов и номера страниц.

**Постусловие:** Студент получил ответ и может скопировать его или задать новый вопрос.

**Альтернативный поток:**

- Если в базе нет подходящих фрагментов, система выводит: *«К сожалению, в загруженных документах нет информации по этому вопросу».*
- Если нейросеть недоступна, система выводит: *«Сервис временно недоступен. Попробуйте позже».*

## Сценарий 2: Уточняющий вопрос

**Актёры:** Студент, Система.

**Предусловие:** Студент уже задал вопрос и получил ответ.

**Основной поток:**

1. Студент читает ответ и хочет уточнить: *«А какие бывают виды АСОИУ?»*
2. Вводит уточняющий вопрос в то же поле.
3. Нажимает «Найти».
4. Система ищет в базе фрагменты о видах АСОИУ.
5. Отправляет вопрос и найденные фрагменты в нейросеть.
6. Нейросеть отвечает, перечисляя виды АСОИУ на основе документов.
7. Система выводит новый ответ вместо предыдущего.

**Примечание:** каждый вопрос обрабатывается независимо, контекст прошлого вопроса не учитывается. Поэтому уточняющий вопрос должен содержать ключевые слова (например, «АСОИУ»), а не только «а какие бывают виды?».

## Сценарий 3: Загрузка нового документа (для администратора)

**Актёры:** Администратор, Система.

**Основной поток:**

1. Администратор кладёт PDF-файл с лекцией в папку `data/`.
2. Запускает команду индексации в терминале.
3. Система извлекает текст, разбивает его на абзацы и строит индекс BM25.
4. Администратор видит сообщение: *«Индексация завершена. Документов: 5, фрагментов: 120».*

**Примечание:** в MVP загрузка документов выполняется через командную строку. Загрузка через веб-интерфейс — возможное развитие.
